# 위베이프 고객 예약 관리 (미취급 상품 예약 + AS 접수)

## 2026-08-10 업데이트 (6) — 홈 화면을 "처리 현황판(단계 보드)"으로 전면 재설계
시안 3개(액션 홈 / 단계 보드 / 카운터 홈)를 만들어 검토한 결과 **"단계 보드"** 로 확정해서 적용했습니다.

**왜 바꿨나**: 이전 홈(통합 피드)은 처리중인 AS 324건을 그냥 나열해서 벽처럼 보였고, 그중 295건이 "3일 이상 지연"이라 빨간 경고가 사실상 의미가 없었습니다. 목록을 다 보여주는 게 답이 아니라, **어느 단계에 몇 건이 걸려있는지**를 보여주는 게 곧 "지금 뭘 해야 하는지"라서 보드 방식으로 바꿨습니다.

- **로그인하면 바로 "처리 현황판"이 뜹니다.** 사이드바 첫 메뉴이고, 언제든 다시 들어올 수 있습니다.
- **AS 보드는 두 개**입니다 — 본사 제품(접수 → ERP 기입완료, 2칸)과 타사 제품(지점접수 → 로데오점 확인 → 제조사 검사중 → 재입고 → 지점발송 → 수령완료, 6칸). 흐름이 서로 달라서 따로 보여줍니다. 아래에 상품 예약 흐름(검토대기 → 발주가능 → 입고완료 → 연락완료 → 구매완료, 5칸)도 같은 방식으로 있습니다.
- 각 칸에 **건수와 최근 3건이 미리보기**로 보이고, 3일 넘게 밀린 건이 있는 칸은 **빨갛게** 표시됩니다.
- **칸을 누르면 그 단계만 걸러진 목록으로 바로 들어갑니다.** 목록 위에 "○○ 단계만 보는 중" 안내가 뜨고, 버튼 하나로 전체 보기로 돌아올 수 있습니다.
- 맨 위 요약 카드 4개: AS 처리중 / 3일 이상 밀림 / 고객 연락 차례 / 예약 대기.
- **"보는 범위" 드롭다운**이 현황판·상품 예약·AS 접수 세 화면에 공통으로 있습니다. **전체 매장**으로 합쳐 보거나 매장 하나만 골라 볼 수 있고, 한 곳에서 바꾸면 나머지 화면도 같이 따라갑니다. 전체 매장으로 볼 때는 목록 각 줄에 매장명이 굵게 표시됩니다.
- 이전의 "매장 런처", "통합 피드" 홈 화면은 제거했습니다.
- 오프라인 테스트 전체 통과 확인 후 배포했습니다.

## 2026-08-10 업데이트 (5) — 홈 화면을 "통합 피드"로 재설계 (매장을 안 골라도 여기서 바로 확인)
"매장을 찍어서 들어가는 게 아니라, 처음부터 여기서 다 보이면 좋겠다"는 피드백으로 (3)에서 도입한 "매장 런처(카드 그리드, 클릭해서 매장 진입)"를 다시 갈아엎었습니다. 시안 3개(통합 피드 / 매장별 섹션 / 관제 보드)를 먼저 만들어 검토 후, "통합 피드"로 확정해서 적용했습니다.
- **로그인하면 매장을 고르지 않고도 전 매장의 처리할 일이 바로 한 화면에 모여 보입니다.** AS와 예약이 헷갈리지 않도록, 왼쪽에 "AS 접수" 컬럼(빨간 점) · 오른쪽에 "상품 예약" 컬럼(파란 점)으로 확실히 나눠서 보여줍니다. 각 항목 카드도 색 테두리로 AS/예약을 구분합니다.
- 완료되지 않은(처리중) 항목만 모으고, 3일 이상 밀린 AS는 지연 배지로 강조합니다. 맨 위 요약 카드에 "AS 처리중 / 3일 이상 지연 / 예약 대기 / 전체 매장" 숫자가 바로 보입니다.
- 상단 필터 칩으로 "전체/AS만/예약만" + 매장별로 좁혀볼 수 있고, 매장 칩을 하나 고르면 그 매장 화면을 바로 여는 버튼도 같이 뜹니다 (처리할 일이 하나도 없는 매장도 들어가서 새로 등록할 수 있도록).
- 항목 카드를 클릭하면 그 매장의 AS 접수/상품 예약 화면으로 바로 이동해서 해당 건의 상세까지 열어줍니다 — 매장 고르고 → 탭 찾고 → 항목 찾는 단계를 한 번의 클릭으로 줄였습니다.
- 화면 안에서는 여전히 "현재 매장 · 매장 변경" 표시로 언제든 홈(통합 피드)으로 돌아올 수 있습니다.
- 오프라인 테스트에 새 홈 피드 흐름(로그인→피드 확인→매장 필터→매장 바로 열기→피드 항목 클릭→상세 진입) 검증 케이스를 추가해서 전체 통과 확인했습니다.

## 2026-08-10 업데이트 (3) — 로그인 직후 "매장 런처" 홈 화면 도입 (예약/AS 둘 다 매장 고정)
"전체 매장 합산해서 볼 필요 없다, 지점별로 바로 들어가는 버튼을 만들어달라"는 요청으로, 시안 3개를 먼저 만들어 검토 후 "매장 런처(홈 그리드)" 안으로 확정해서 적용했습니다.
- **로그인하면 바로 매장 선택 화면(홈)이 뜹니다.** 매장마다 카드가 하나씩 있고, 카드에 그 매장의 "AS 처리중 건수"와 "예약 대기 건수"가 바로 보입니다. 3일 넘게 처리 안 된 매장은 카드에 빨간 경고 점이 뜹니다. 내 소속 매장 카드는 노란 테두리로 구분됩니다.
- **카드를 누르면 그 매장의 예약/AS 화면으로 바로 들어갑니다.** 상품 예약·AS 접수 화면에서 "전체 매장" 옵션은 없앴습니다 — 이제 항상 하나의 매장 화면만 보게 됩니다. 화면 위쪽에 "현재 매장: OOO · 매장 변경" 표시가 있어서 언제든 다른 매장으로 바꿀 수 있습니다.
- 마지막으로 보던 매장은 기억해뒀다가, 다음에 로그인하면 그 매장 화면으로 바로 들어갑니다 (홈 화면을 매번 다시 거칠 필요 없음).
- 새 접수/새 예약 등록 시 매장 선택 기본값도 "지금 보고 있는 매장"으로 자동 지정됩니다.
- **예약 통계 / AS 통계 화면은 그대로 둡니다** — 이 두 화면은 원래 매장 간 비교가 목적이라 "전체 매장" 옵션이 계속 필요합니다.
- 오프라인 테스트에 새 홈 화면 흐름(로그인→매장 선택→진입→매장 변경→재진입) 검증 케이스를 추가해서 전체 통과 확인했습니다.

## 2026-08-10 업데이트 (2) — 통계 화면 월별 필터 + 기간 직접 설정 (예약/AS 둘 다)
- **예약 통계에도 "월" 필터가 새로 생겼습니다** (AS 통계에만 있던 기능). 최근 12개월 중 골라서 그 달 등록분만 볼 수 있습니다.
- **기간 선택에 "기간 직접 설정"이 추가됐습니다** — 프리셋(최근 7/30/90일) 대신 시작일·종료일을 직접 골라서 그 사이 데이터만 볼 수 있습니다. 예약 통계·AS 통계 둘 다 동일하게 동작합니다.
- 우선순위는 **월 선택 > 기간 직접 설정 > 최근 N일 프리셋 > 전체 기간** 순입니다. 월을 고르면 기간 필터는 비활성화(직접 설정 입력칸도 숨김)됩니다.
- AS 통계의 기간 필터(최근 N일/직접 설정)는 이번에 **실제 접수일(received_date) 기준으로 고치기도 했습니다** — 예전에는 "DB에 입력된 시각" 기준이라, 스프레드시트에서 옮긴 과거 데이터가 마치 "최근 며칠 사이 접수"인 것처럼 잘못 잡히는 문제가 있었습니다.
- 오프라인 테스트(`node test/run-test.js`) 통과 확인.

## 2026-08-10 업데이트 (1) — AS 목록 날짜/순서 버그 수정 + AS 접수 화면 시안성 개선 (매장 선택 · 현황 파악)
현장에서 매일 여러 명이 쓰는 화면이라 "어느 매장 건인지 헷갈림"과 "매장별로 지금 어떤 AS가 쌓여있는지 한눈에 안 보임" 문제를 개선했습니다.
- **AS 접수 상단에 매장별 현황 스트립 추가**: 필터와 무관하게 항상 전체 매장의 "처리중 건수"를 카드로 보여줍니다. 3일 이상 처리 안 된 매장은 카드가 빨간 테두리로 바뀌고 "⚠ 최대 N일째"가 표시됩니다. 카드를 클릭하면 그 매장으로 바로 필터링됩니다.
- **"전체 매장" 보기일 때 목록을 매장별로 묶어서** 표시합니다 (매장명 + 전체/처리중 건수 소제목). 상품 예약 목록도 동일하게 매장별로 묶었습니다.
- **목록 각 줄에 등록한 직원 이름과 경과일수(며칠째)를 표시**합니다. 검색창에서도 고객명뿐 아니라 등록자 이름으로 찾을 수 있습니다.
- **새 접수 등록 모달에서 매장 선택 필드를 맨 위로 옮기고 노란 박스로 강조**했습니다 ("본인 소속 매장이 기본 선택되어 있고, 다른 매장 대신 접수할 때 여기서 바꾼다"는 안내 문구 포함). 상품 예약 등록 모달도 동일하게 바꿨습니다.
- 오프라인 테스트(`node test/run-test.js`) 전체 통과 확인.

## 구성
- `schema.sql` — Supabase에 테이블/함수를 만드는 스크립트
- `index.html` — 앱 전체 (이 파일 하나로 동작, 별도 서버 코드 없음)

## 배포 순서

1. **Supabase 테이블 만들기 (이번에 schema.sql이 업데이트됐습니다 — 꼭 다시 실행해주세요)**
   - 기존 위베이프 POS가 쓰는 Supabase 프로젝트를 엽니다.
   - 왼쪽 메뉴 SQL Editor → New query → `schema.sql` 내용을 통째로 붙여넣고 Run.
   - 완료되면 `resv_`로 시작하는 테이블 5개(stores, staff, reason_options, product_requests, as_requests)가 생깁니다. 기존 POS 테이블과는 이름이 겹치지 않습니다.
   - 사진 첨부 기능을 위해 `resv-photos`라는 공개(public) Storage 버킷도 자동으로 함께 만들어집니다. Storage 메뉴에서 버킷이 생겼는지 확인해보세요.
   - 이번 업데이트로 `resv_staff`에 실제 재직 중인 직원 17명이 추가되고, `resv_as_requests`에 AS 접수용 컬럼(제품구분, 접수방식, 불량사유 등)이 추가됩니다. 기존에 이미 schema.sql을 한 번 돌린 상태여도 그대로 다시 실행하면 안전하게(중복 없이) 반영됩니다.
   - **새로 추가된 직원 17명은 전부 PIN `0000`, 소속 매장 미지정 상태로 들어갑니다.** 배포 후 설정 탭에서 각자 소속 매장을 지정하고 PIN을 실제 사용할 값으로 바꿔주세요.

2. **접속 정보 입력**
   - Supabase 대시보드 → Settings → API 에서 `Project URL`과 `anon public` 키를 복사합니다.
   - `index.html` 상단의 아래 두 줄을 실제 값으로 바꿉니다.
     ```js
     const SUPABASE_URL = 'https://YOUR-PROJECT.supabase.co';
     const SUPABASE_ANON_KEY = 'YOUR-ANON-KEY';
     ```

3. **배포**
   - 기존 POS와 같은 방식(Vercel)을 추천합니다. `index.html`이 있는 폴더를 그대로 Vercel에 새 프로젝트로 올리면 끝입니다(정적 파일이라 빌드 설정 필요 없음).
   - Vercel 계정에 로그인 후 `vercel` CLI로 이 폴더에서 `vercel --prod` 실행하거나, GitHub 저장소에 올려서 Vercel과 연결하면 됩니다.

4. **첫 로그인**
   - 스크립트에 기본 계정이 하나 들어있습니다: 이름 `실장님`, PIN `0000`, 권한 실장.
   - 배포 후 바로 로그인해서 설정 탭에서 **실제 직원 이름과 PIN으로 다 바꿔주세요.** 기본 계정(실장님/0000)은 반드시 비활성화하거나 PIN을 변경하세요.

## 화면 구성
- **상품 예약 (미취급·품절)**: 좌측 목록 + 우측 상세패널 구조. 미취급/품절 탭 구분, 전체 매장 중 선택 등록. 문의접수 → (실장님 검토: 발주가능/불가) → 발주가능 → 입고완료 → 연락완료 → 구매완료/구매포기
- **AS 접수** (이번에 전면 개편): 본사 제품 / 타사 제품 탭으로 구분해서 접수합니다.
  - **본사 제품**은 실제 취급 제품 카탈로그에서 검색해서 고를 수 있고, 목록에 없으면 "직접 입력"도 가능합니다. 그래피티C·그래피티3·롤리팟-J처럼 관리 중인 제품은 고르면 자동으로 정해진 불량사유 목록(작동불량/누수/인식불량 등)이 뜨고, 상세 내용을 추가로 적을 수 있습니다.
  - **본사 제품 처리 흐름**: 접수 완료 → ERP 기입 완료 (2단계, 목록/상세에서 점 2개짜리 진행 표시줄로 보여줍니다)
  - **타사 제품 처리 흐름**: 지점 접수 → 로데오점 접수확인 → 제조사 발송·검사중 → 재입고 완료 → 지점 발송완료 → 고객 수령완료 (6단계)
  - 접수방식(현장교체/단순접수), 연락처 수집방식(전체번호/뒷4자리만)도 함께 기록합니다. 단계는 "처리" 버튼으로 다음 단계로, "이전 단계로" 버튼으로 되돌릴 수 있습니다.
- **사진 첨부**: 상품 예약·AS 접수 등록 시 사진을 최대 5장까지 첨부할 수 있고, 등록 후에도 상세화면에서 "+ 사진 추가"로 계속 추가할 수 있습니다. 브라우저에서 자동으로 리사이즈·압축(최대 1280px, JPEG) 후 업로드해서 용량을 아낍니다.
- **통계**:
  - **AS 통계**는 이번 개편으로 "중복 증상 TOP"이 메인입니다 — 같은 제품에서 같은 불량사유가 반복되는 순으로 랭킹을 보여주고, 클릭하면 그 사례들(매장/고객명/날짜/상세내용)이 바로 펼쳐집니다. 그 아래로 제품별 접수 Top10, 매장별 비교도 볼 수 있습니다.
  - **예약(상품 문의) 통계**는 기존과 동일합니다 — 매장/기간 필터, 상품 Top10 랭킹, 접수 사유별 통계, 발주가능·불가 비율, 입고 후 구매전환율, 매장별 비교.
- **설정** (실장/관리자 전용): 직원 추가·PIN 재설정, 접수 사유 목록 관리
